Learnings :


- Si un fetch est effectué dans un handler, toujours penser à faire const handleSubmit = *async* (e) => {}
- Par défaut, lors d'un onSubmit d'un form, le navigateur déclenche un refresh de la page, donc on pense toujours à e.preventDefault()
- Lors d'un fetch :

  - On note l'URL complet "http://localhost:3000/auth/signup".
  - On oublie pas le header pour préciser qu'on envoie en json : header**S** : { "Content-Type" : "application/json" }
  - Si on veut la réponse du fetch (si on l'a stocké dans un const res par exemple) --> const data = await res.json();
  - Puis pour lire la réponse if(!res.ok){alert(data.error)}
- Check dans la DB

  - psql (Client en ligne de commande de PostGres)
  - -U = User (Se connecter avec un utilisateur) postgres (l'utilisateur admin par défaut)
  - -h localhost (host, notre machine locale)
  - psql -U postgres -h localhost : Ouvre un terminal connecté à PostgreSQL en local avec l'user postgres
  - En vrai : npx prisma studio et on a l'interface graphique aussi hein


- data vs res
  - res = réponse HTTP (status, ok, headers) ---> const res = await fetch()
  - res contient la réponse HTTP brute, si on fait console,log(res) on obtiendrait : Response {
    status: 200,
    ok: true,
    headers: ...
    body: ReadableStream
    }
  - data = contenu JSON ---> const data = res.json()
  - en faisant res.json() on transforme le body de res en objet JS, donc console.log(data) : data = {
    message: "Logging Successful",
    user: { id: 1, username: "yoann", email: "yoann@test.com" }
    }
  - res.ok c'est un raccourci pour dire "status code entre 200 et 299". Donc request successful
  - En conclusion : res -> Contrôle status / data -> contenu (mesage, user, error).
