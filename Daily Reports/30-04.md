Learnings :

- CI (Continuous Integration) : Vérifie le projet automatiquement à chaque push sur la branche main. À chaque push sur main, github va :
  - 1 - Récupérer le repo
  - 2 - installer node
  - 3 - installer les dépendances backend
  - 4 - installer les dépendances frontend
  - 5 - builder le frontend
- Si une étape échoue, github marque la CI en rouge, dans l'onglet "Actions" du projet.



- En résumé, à chaque git push, gitHub prend le code :
  - Le met dans une machine propre (Linux vierge)
  - Installe les dépendances
  - Build le frontend
  - Vérifie que tout fonctionne

Le but de la manoeuvre? Vérifier que le projet fonctionne dans un environnement neutre. C'est comme ça que fonctionnent les boîtes en prod.

En entreprise, le process d'ajout/modif de feature est tel que :

- 1 : On part de la branche main à jour
- 2 ; On crée une nouvelle branche
- 3 : On code la feature
- 4 ; On teste localement
- 5 : On commit / push la branche
- 6 : On crée une PR sur github, en choisissant main et la branche qu'on souhaite push.
- 7 : Les checks définit dans ci.yaml s'exécutent. SI ils sont successful, le push peut être accepté.
